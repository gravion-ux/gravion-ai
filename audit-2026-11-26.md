# Gravion AI — Local Audit (26 Nov 2026)

Scope: local build at `~/workspace/github-projects/gravion-ai/` (v0.11.0, uncommitted working tree over last commit 3190cca "piece 3"). Nothing published by this audit. Tests run: **400 passed in 9.62s** (`.venv/bin/python -m pytest -q`).

## What it actually is

A modular AI **platform framework** in pure Python (only runtime dep: `cryptography>=41`). It is not a trained model: Gravion Core is a deterministic rule-based echo responder (`providers.py: GravionCoreProvider.complete` returns `[gravion-core] You said: …`). Real intelligence comes only when an operator connects an OpenAI-style chat-completions endpoint. The README states this honestly ("Parameter honesty" section); `data/models.json` is less honest — it marks 10 models `available` with notes like "first trained bundle ships at Tier 2", although no weights exist in the repo. That wording is the single biggest credibility risk in the project.

## Strengths (verified in code)

- **Clean module system:** 10 modules (chat, support, coder, image, music, video, website-builder, cyber, agentic, all-in-one), each a manifest + `run(ctx, prompt)` entrypoint behind one registry (`registry.py`). Runtime path is disciplined: gate → signed-manifest verify (production) → catalog model resolution → module run.
- **Licensing subsystem is genuinely strong:** Ed25519 deployment identity (private key 0600, never transmitted), issuer-signed licenses + module manifests with SHA-256 file hashes, hash-chained tamper-evident audit log, 4-field privacy-pinned entitlement protocol with signed 900s tokens + offline cache, safe suspension (export always works, no kill switch), governed self-upgrade (signed packages, changelog-before-activation, retained versions, auto-rollback), hosted authority HTTP service.
- **Config hardening (Unreleased):** unknown fields rejected, URL rules (no embedded credentials/query/fragment), HTTPS required for remote endpoints in production, stored API keys refused in production, timeouts bounded 1–300s, `gravion doctor` read-only readiness checks.
- **Provider plumbing safety:** message validation, 4 MiB response cap, HTTP status without upstream body leak, injectable opener for tests. Endpoint contract is generic chat-completions — any compatible server works.
- **Web UI exists and is safe-by-default:** stdlib ThreadingHTTPServer on loopback, file attachments (8 files/2 MiB/8 MiB caps, sanitized names, SHA-256 manifests, text extraction, binary metadata-only), no-store/nosniff headers, bot-slot routing.
- **Training data pipeline (local half) is real:** strict JSONL validation, dedupe, deterministic hash-ordered train/validation split, hashed dataset report (`training/datasets.py`); job validation against catalog/registry (`training/jobs.py`) with an honest "no training backend" refusal.
- **Test coverage is broad:** 400 tests across 25 files, CI matrix Python 3.10–3.12 with coverage + CLI smoke test.

## Issues found

1. **Registry honesty gap:** `models.json` claims trained bundles "available" for chat/code/vision/audio/video/builder/shield/agent/omni; the code ships brief-generators + local dev renderers only. Fix wording to "bundle packaging ready; weights are an operations step" everywhere, matching the README.
2. **Modules mostly produce briefs, not outputs:** image/music/video/cyber/agentic modules parse intent and build a structured brief for a model; with Gravion Core they return echo text. Only video (local MP4 render), website-builder (real static site), and agentic (plan file) produce tangible artifacts offline.
3. **No conversation state:** every call is single-turn (system + one user message). No history, sessions, or memory — chat/support feel stateless; web UI has no thread persistence.
4. **No streaming:** provider is request/response only; no SSE/token streaming in CLI or web. Modern AI UX expects streaming.
5. **No RAG/knowledge grounding:** support module is policy-grounded only via system prompt; no document ingestion, embeddings, or retrieval. Uploaded files are prompt-stuffed (24k char cap), not indexed.
6. **No tool execution:** agentic module writes plans and explicitly executes nothing. No function-calling/tool protocol in the provider layer (messages are text-only, roles limited to system/user/assistant).
7. **Provider layer is minimal:** single endpoint, no retries/backoff, no fallback chain, no per-module model routing beyond catalog resolution, no token/cost accounting, no temperature/max-tokens controls exposed.
8. **Web UI is a single inline HTML string:** no auth (relies on reverse proxy), no rate limiting, no conversation history UI, no streaming, file input is base64-in-JSON (fine locally, poor at scale). `GravionRuntime` is constructed once per server — config changes need restart.
9. **Sync-only:** stdlib sync HTTP + urllib; no async. Fine for local/single-tenant, a ceiling for multi-user serving.
10. **Trainer is a separate, unintegrated project:** `gravion-trainner` (audit copy at `audit-all-2026-11-25/gravion-trainner/`, v0.2.0) evaluates endpoints with substring-coverage scoring. Gravion AI's training package never calls it; there is no eval gate in the upgrade/training flow, and no shared dataset format (trainer uses `{id, prompt, expected_contains}`, datasets.py uses `{prompt, completion}`).
11. **Working tree far ahead of git:** pieces 4–11 + production hardening are uncommitted/untracked (17 modified, ~30 untracked files). Published GitHub version is v0.3.0-era (piece 3). Risk of loss; also `__pycache__`/`.pytest_cache`/egg-info noise in tree.
12. **No packaging/ops artifacts:** no Dockerfile, no systemd unit, no OpenAPI spec for the web/authority APIs, no structured logging/metrics/health endpoint beyond `/api/status`, no SBOM/release process. Version in `pyproject.toml` is 0.11.0 but CHANGELOG "Unreleased" hardening is unversioned.
13. **All-in-one routing is crude:** `<module>:` directive prefix only; no intent classification fallback.
14. **Long-form video pipeline is spec-only** (ARCHITECTURE §7) — scene planning/stitching not implemented; local renderer is short-clip only.

## Missing production features (gap to "production-ready")

- Trained/hosted weights or a first-class hosted endpoint story (currently BYO endpoint).
- AuthN/AuthZ + multi-tenancy for web/authority (users, roles, API keys per deployment).
- Conversation persistence + memory; streaming responses.
- RAG: ingestion, chunking, embeddings, vector store, citations.
- Tool/function calling with sandboxed execution for the agentic module.
- Observability: structured logs, metrics, tracing, cost/usage accounting, eval gates (wire in gravion-trainner).
- Reliability: retries, circuit breaker, provider fallback, rate limiting, request queues.
- Deployment: Docker image, reverse-proxy/TLS guide with concrete config, backup/restore drill, release signing + PyPI publish.
- Legal: commercial license template still needs lawyer review (noted in PRODUCTION.md).

## Prioritized improvements

**P0 — credibility & safety (do first)**
1. Fix `models.json` honesty wording; add a registry "weights_status" field so "available" can't imply trained weights.
2. Commit the working tree in piece-sized commits; tag v0.11.0; publish (local 400-test suite already green).
3. Add provider retries with backoff + timeout/cost logging; expose temperature/max_tokens.

**P1 — core product feel**
4. Conversation sessions: persistent threads (SQLite under `data/`), history in CLI + web.
5. Streaming: SSE in web API + provider streaming interface.
6. RAG-lite: ingest uploaded/docs into a local index (stdlib-friendly: TF-IDF or sqlite-vec later), support module answers with citations.
7. Wire Trainer in: shared dataset format, `gravion train eval` gate before upgrade activation.

**P2 — platform depth**
8. Tool-calling protocol + sandboxed tool runner for agentic (files/code/API tools, permission-scoped).
9. Auth + rate limiting in web server (token auth option), OpenAPI spec, structured JSON logging + `/healthz`.
10. Docker + compose, release workflow (signed tags, PyPI), SBOM.

**P3 — differentiators**
11. Intent-based all-in-one routing; per-module model routing table.
12. Long-form video pipeline (scene plan → stitch) on top of existing renderer.
13. Multi-provider fallback chains and cost budgets per tier.

## Verdict

Architecture and licensing are production-grade; the intelligence layer is a scaffold. The fastest path to a credible "production-ready" claim: honesty fix + commit/publish, then sessions + streaming + RAG-lite + Trainer eval gate. Weights remain an operations decision (hosted endpoint), not a code gap.
