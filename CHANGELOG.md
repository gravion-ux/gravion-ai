# Changelog

## Unreleased

- Cyber and support correctness: cyber severity now also records the criticality and danger-level labels ("criticality: high", "danger level high"), while urgency and priority labels stay unrecorded as triage urgency. Support escalation now hands over the executive asked for by role ("executive se connect karo", "executive ko bulao"), while the singular "human resource" topic and a callback declined one verb later ("call back karna mat") stay with the bot and "call back karna hai" still escalates. Fixed a stale degree-form stem assertion left behind by the size-synonym stems ("larger" lands on "big"). Refreshed the cyber and support manifest hashes and recorded the fixes as corrected mistake cases with regression tests.

- Cyber and text correctness: cyber severity now records the numbered scale ("sev1 incident" is critical, "sev-2" high, "sev 3" medium, "sev4" low), impact/risk/threat-level labels ("impact: critical", "risk: high") and the everyday level words on the finding itself ("a severe issue" and "a major incident" are high, "a minor bug", "a trivial issue" and "a negligible risk" are low, "a blocker bug" and "a catastrophic failure" are critical), while declined forms ("not a severe issue") state no level and priorities ("p1 incident", "low priority") stay unrecorded as triage urgency. The shared stemmer now also matches size, speed and everyday verb synonyms ("large" with "big", "tiny" with "small", "quick" with "fast", "begin" with "start", "display" with "show", "finish" with "complete"), so "who started the work" finds "she began the work" and a "fast animal" query ranks "the quick fox ran" instead of scoring it zero. Refreshed the cyber and summarization manifest hashes and recorded both fixes as corrected mistake cases with regression tests.

- Text and support correctness: the shared stemmer now matches synonym and spelling-variant stems ("purchase" with "buy", "automobile" with "car", "colour" with "color", "kid" with "child"), so "what did she buy?" finds "she purchased a bicycle" instead of document Q&A reporting no answer and a "car" retrieval query ranks the automobile passage instead of scoring it zero. Support escalation now hands over Hinglish person requests asked for by the send verb ("insaan ko bhej do"), the senior by the call verb ("senior ko bulao"), the team named as its person ("customer care wala chahiye", "help desk se baat") and a phone conversation asked for directly ("phone par baat karni hai", "kisi se baat karni hai"), while declined forms ("kisi se baat nahi karni") and topic namings ("customer care wala number kya hai") still stay with the bot. Refreshed the support and summarization manifest hashes and recorded the fixes as corrected mistake cases with regression tests.

- Text and support correctness: the shared stemmer now matches suppletive comparatives with their bases ("better"/"best" with "good", "worse"/"worst" with "bad", "farther"/"furthest" with "far", "elder"/"eldest" with "old", "less"/"least" with "little"), so "who is good at chess?" finds "she is better at chess" instead of document Q&A reporting no answer; positional -er words ("former", "inner", "upper") keep their form instead of landing on "form"/"in"/"up". Support escalation now hands over the callback asked for by its bare noun ("callback please", "callback chahiye"), the call asked for in Roman Hindi ("mujhe call karo", "call kar do") and the formal person word ("manushya chahiye"), while declined forms ("callback nahi chahiye", "call mat karo") still stay with the bot.

- Measured model specifications: every registry entry that ships weights now has a specification (`data/model_specs.json`, read by `model_spec.py`) carrying the architecture, embedding width, vocabulary and class counts, storage dtype, quantization method, parameter count split by storage dtype, licence, training provenance and a SHA-256 digest of the whole specification. Every measured field is computed from the shipped weights artifact by `tools/build_model_specs.py` and the test suite fails if the checked-in file drifts away from the weights, so the registry can never claim a size the model does not have. Storage dtype and quantization method are reported separately — `int8` is how a tensor is stored, `symmetric-int8` is how it was quantized — and the parameters are counted per dtype, so Gravion Core's 10,586,543 parameters are reported as 10,575,629 int8 plus 10,914 float32 bias and transition weights. The licence, the specification version and an optional base-model lineage are declared; a base model may not reference itself and a lineage may not loop. `gravion models list` now shows the architecture, dtype and quantization beside the size and accepts `--min-parameters`, and the new `gravion models spec <id>` command prints a model's whole specification.

- Text-module correctness: the shared stemmer now matches degree and adverb forms with their bases ("happier"/"happily" with "happy", "faster" with "fast", "quickly" with "quick", "teacher" with "teach"), so a base-form question finds degree-form evidence instead of document Q&A reporting no answer; base words whose ending belongs to the word ("river", "family") keep their form. Summarization now skips near-duplicate sentences in its first selection pass, so summary slots cover distinct points instead of restating one ("Cats sleep." / "Cats sleep a lot."). Removed an unused `Iterable` import from catalog verification, refreshed the summarization manifest hash, and recorded both fixes as corrected mistake cases with regression tests.

- Text-module correctness: the shared stemmer now matches -se/-ve verb forms with their bases ("licensing" with "license", "serving" with "serve", "pleasing" with "please", "receiving" with "receive", "analysing" with "analyse"), so a base-form question finds derived-form evidence instead of document Q&A reporting no answer and retrieval scoring the relevant passage zero; the e-restoration no longer invents "focuse"/"buse" for the "us" bases "focus"/"bus", and "creating"/"arranging" meet "create"/"arrange". Retrieval now says plainly when no supplied passage matches the query instead of listing every passage as a top match at 0.000.

- Mistake learning and catalog verification: local training now records failing tests, wrong routes, weak responses and catalog failures in a mistake log, builds preference pairs from corrected outputs, turns corrected cases into regression tests, and folds corrected outputs plus verified catalog routing examples back into training. Catalog verification loads every bundled model from its stored weights, checks parameter counts and weights hashes against the registry, runs model and module smoke tests, checks module manifest identity and file hashes, and excludes stale entries from verified routing selection. Refreshed stale module manifest hashes and aligned the image module registry version with its manifest.

- Detection, routing and formatting correctness: coder task detection now treats a pronoun-object review ("can you review this?") and a bare clause-final review ("just review, do not rewrite") as reviews. Cyber severity no longer records "not a high severity issue" as high (the negation runs through the article) and records CVSS base scores at their defined bands ("cvss 9.8" is critical); indicator extraction now records defanged bare domains ("evil[.]com") as domain indicators while plain dotted prose stays unrecorded. Support escalation now hands over customers who reject the bot ("i dont want a bot", "bot nahi chahiye") and call-centre requests in both languages. All-in-one routing sends explicit human requests and order-status questions ("where is my order", "mera order kahan hai") to support instead of chat, while a clear intent lead still wins first. Agentic task detection treats workflow/plan and pronoun objects as runs ("start the workflow", "run this every hour"), records bare numbered step lists and "and"-joined final steps, and recognises the calculator tool and "browse" as the browser. The website brief now reads slash/semicolon page lists, "website:" colon lists of known pages, page-name runs ("with cart and checkout", "just home and contact") and "with a blog" namings, and treats redesign/update/fix requests aimed at an existing site as iterate instead of rebuilding it. Image mode treats background changes as edits and records vertical/horizontal shapes; video treats retiming, muting and remove-from requests as edits and widescreen as 16:9; music records the energetic/romantic/peaceful/relaxing/angry moods. Data analysis blanks phone numbers as labels instead of counting their groups as values, and whole-number statistics print in full ("Median: 1000001", not "1e+06"). Sentence splitting keeps "Rs. 500" whole, and the translation phrasebook covers "go", "come", "i love you" and "very good" in both directions.

- Module detection and routing correctness: coder task detection now treats security-hole presence questions ("any security holes in this code?"), handling questions ("does this function handle errors?"), runtime and memory questions ("how long does this code take?") and malfunction statements ("this code is too slow", "my code has a memory leak", "infinite loop in this code") as reviews, and big-O and concept questions ("what is recursion?", "how does sorting work?") as explanations, instead of answering supplied-code questions with new code. Cyber severity no longer records "non-critical" as critical and records a level named on an alert ("this is a critical alert"). Support escalation no longer hands over the identity question "are you human?" and now escalates Hinglish need-a-human requests ("insaan chahiye"), named departments ("talk to sales", "billing se baat karni hai") and the plain operator request. Agentic task detection treats a bot object as a build and start/launch/deploy as run. Image mode treats transform verbs ("resize this image"), bare background removal and "make it brighter" as edits; video records the horizontal shape as 16:9 and subtitle/caption/dub requests as edits. All-in-one routing now reaches image, video, cyber, translation, retrieval and data-analysis for edit, response, translate, search and spreadsheet requests that previously fell through to chat. The shared stemmer matches "woken"/"drawn" with wake/draw and "funguses" with "fungus", and the translation phrasebook covers everyday entries ("help", "happy", "where are you") and the Roman spellings of its own entries ("shubh raatri", "mera naam hai") in both directions.

- Support and cyber routing correctness: support escalation now treats "customer support" as the team service name it is, so "talk to customer support" and "connect me with customer support" hand over to a person while topic questions ("what are your customer support hours?") and negated requests still stay with the bot. Cyber task detection now treats triage verbs aimed straight at a named indicator ("prioritize CVE-2026-12345", "assign 10.0.0.8 to SOC") as triage, like the bare "triage" verb, instead of falling through to analysis.

- Coder, support and website-brief correctness: coder task detection now treats print/log/display questions ("what does this code print?"), complexity questions, run-outcome questions ("what happens when this code runs?"), a bare trace and a code summary as explanations, and compile/run correctness questions ("does this code compile?", "will this code work?") and speed questions ("how fast is this algorithm?") as reviews, instead of answering questions about existing code with new code. Support escalation now honours Hindi negators before the phrase ("nahi chahiye human", "mat karo escalate") as well as after it, escalates the team named in Roman Hindi ("customer care se baat karni hai") and a verb-gated live-chat request ("connect to live chat"), while topic questions ("how does live chat work?") still stay with the bot. The website brief now collects a space-separated page enumeration ("home about contact pages") instead of dropping every page but the last.

- Cyber task and indicator correctness: "report" and "triage" used as nouns no longer trigger a report or triage task — a determiner directly before the word ("the report mentions CVE-2026-12345", "this triage report covers…") marks discussion of an existing artefact, while creation verbs ("file a report", "draft the report") still request one. Indicator extraction now records MD5 and SHA-1 hashes under their own kinds (a shorter pattern never matches inside a longer hash), and URLs keep balanced parentheses or brackets that belong to the address ("…/Buffer_(computer_science)", IPv6 literals) while still trimming a sentence's own closing punctuation. Removed the unused `rng` parameter from the sunset-lighting image helper.

- Cyber and text correctness, second pass: cyber task detection now treats a triage or report verb aimed straight at a named indicator ("triage CVE-2026-12345", "report 10.0.0.8") as triage/report instead of falling through to analysis, while analysis openers still win ("explain triage for CVE-2026-12345" stays analysis). The shared plural stemmer now matches "oes" plurals ("heroes" with "hero", "potatoes" with "potato") and suppletive plurals ("children" with "child", "women" with "woman", "indices" with "index", "lives" with "life"), so a question about heroes finds a document about a hero. Sentence splitting keeps numeric abbreviations whole ("No. 5", "Fig. 3", "Jan. 5", "approx. 5") and dotted acronyms ("U.S.A.") instead of quoting fragments as sentences, while the same words still end real sentences without a following digit.

- Coder, cyber and text correctness: coder task detection now lets the opening verb govern, so "write a code review tool" generates and "explain code review process" explains instead of both being misread as review requests. Cyber indicator extraction records exact artefacts: sentence punctuation is stripped from URLs, CVE sequence numbers are taken whole instead of truncated, and a four-group window inside a longer dotted version string no longer yields a phantom IPv4 address. The shared plural stemmer now matches irregular -sis plurals ("analyses" with "analysis") and leaves "news" and "lens" whole, and summarization keeps the opening sentences instead of returning an empty summary when every sentence is stopwords alone.

- Support escalation scope: a negator now cancels an escalation request only when it governs the escalation phrase itself — same clause (commas break clauses) and within the four words immediately before it. Previously any negator earlier in the sentence suppressed the handoff, so "I am not happy, get me a human" and "no, I need a human" never reached a person; governing negations ("do not escalate", "please do not get me a human") still suppress as before.

- Text and brief correctness, third pass: document Q&A, retrieval and summarization now share one plural stemmer, so a question about a "class" matches a sentence about "classes" instead of wrongly reporting no answer, and a retrieval query for "cats" scores the passage about a "cat". Retrieval keeps multi-line passages whole instead of truncating them to their first line. Translation's greedy phrase matching now spans the phrasebook's longest entry, so "how much does this cost" matches inside a longer sentence. Music and video durations add compound parts ("2 minutes 30 seconds" is 150), read fractional values ("1.5 minutes" is 90) and accept hours. Support escalation no longer fires on topic phrases ("password manager", "user agent", "human readable"), negated requests ("do not escalate", "no human needed") or name introductions ("call me Priyanshu"). Removed the unused `module_name` parameter from the upgrade restorer.

- Text-module correctness, second pass: data analysis no longer reads a hyphen glued to a digit as a minus sign, so a range "5-10" sums to 15 instead of -5 and dates stop contributing negative values; digits inside a word ("version2") are not numbers. Summarization drops exact duplicate sentences before scoring, so a summary can no longer be one repeated sentence three times. Retrieval now ranks with inverse-document-frequency weighting and drops stopwords, so a passage carrying the query's distinctive terms beats one padded with common words. Removed the unused `KeyPair.can_sign` property.

- Text-module correctness: sentence splitting now keeps a trailing unpunctuated sentence and no longer splits on decimal or abbreviation dots ("3.14", "Dr."), so summaries stop losing their final line and document Q&A can quote an answer from it. Data analysis now parses grouped thousands (Western "1,000" and Indian "1,00,000") and scientific notation instead of fragmenting them into wrong statistics, reports "no mode" when every value appears once and lists tied modes, and removed an unused import.

- Model catalog expansion (text types): added five specialists with their own modules and deterministic local engines — **Gravion Translate** (Hindi/English/Hinglish phrasebook translation, 36,192 parameters), **Gravion Summary** (extractive summarization, 34,983 parameters), **Gravion Search** (sparse-embedding passage retrieval, 39,404 parameters), **Gravion Analyst** (descriptive statistics from supplied numbers, 36,887 parameters) and **Gravion DocQA** (extractive document Q&A, 35,741 parameters), each trained from 192 Gravion-owned seed examples across 48 answer classes with parameter counts computed from stored quantized weights. Gravion Omni retrained over the expanded corpus (3,132 examples, 782 classes, 5,549,315 parameters) and now serves every capability. Translation outside the phrasebook is marked rather than guessed, and document Q&A states plainly when a document holds no answer.

- Model catalog expansion: added **Gravion Support** (dedicated customer-support specialist, 192 Gravion-owned seed examples, 48 answer classes, 32,515 parameters counted from stored quantized weights) and **Gravion Review** (code-review specialist, 192 examples, 48 classes, 33,191 parameters), each with included local sparse n-gram weights and deterministic fallback. Catalog integrity tests now assert every registry entry resolves to a bundled local model and an implemented module type, with an available model serving every capability in every tier.

- Local training validation: training now rejects prompts and completions with no word tokens (a punctuation-only prompt previously trained an exact-match entry for the empty normalized prompt, making every empty prompt a confident match) and rejects conflicting completions for the same normalized prompt instead of silently keeping the last one. Exact-prompt keys in weights artifacts must be non-empty normalized prompts, and an empty prompt is never a confident match at inference. Removed the unused `DEFAULT_BUCKETS` constant.
- All-in-one routing: directives are now case-insensitive and the space after the colon is optional (`coder:fix this` routes to coder instead of silently falling back to chat). Requests without a directive route by a conservative intent check — a clear verb-plus-object signal for exactly one module (code fence, CVE id, `write a python function`, `build a website`) selects that module; anything ambiguous still goes to chat. Removed two unused licensing imports.

- Local Gravion Core training: Gravion Core now includes a sparse n-gram embedding + direct linear softmax classifier trained only from the bundled Gravion corpus (5,657 examples, 779 answer classes; 10,586,543 parameters counted from stored quantized weights; held-out eval 1,238/1,530, 80.9%, versus 0/1,530 for the earlier 750-parameter seed model), with local `gravion-core` training jobs saving verifiable artifacts under deployment `data/models/` and deterministic fallback when weights are missing, invalid, or not confident. Legacy v1 artifacts remain loadable.
- P0 runtime reliability: model registry now carries explicit `weights_status` values so `available` cannot imply included trained weights; endpoint provider gained bounded retries/backoff, timeout/duration logging with redacted metadata, optional temperature/max_tokens, and Gravion request IDs; runtime now writes a persistent content-free run/session event log at `state/run-events.jsonl`.
- Production hardening: strict deployment config validation (unknown fields, endpoint URL rules, production HTTPS for remote endpoints, no stored API keys in production config), safer endpoint-provider errors (bounded responses, text-only content, HTTP status without upstream body leaks), and `gravion doctor` readiness checks.
- Web UI: `gravion web serve` runs a local browser workspace with module chat and file attachments. Files are stored under the deployment data directory, text is extracted for context, and binary files are stored with metadata only.
- Bot slot: `gravion bot status|check` inspects a drop-in slot for an operator-owned bot. The slot validates an HTTP manifest only; Gravion never executes dropped bot code and never recreates the operator's bot.
- Documentation: production runbook, web UI guide, and bot-slot input checklist.
